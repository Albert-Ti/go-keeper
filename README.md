# GoKeeper

Приложение которое хранит приватные данные пользователя

**Технологии:**

- **Storage** - Postgres + AWS3 + Redis.
- **Server** - gRPC + protobuf + SMTP.
- **Client** - BubbleTea.

## Auth

1. При регистрации пользователь обязан будет подтвердить почту, тут 2 способа: если подключен SMTP server, то код придет на почту(требуется реально существующая почта), если нет, то придет на клиент(вообще этого в проде не должно быть, но это сделано для упрощения ревью).
2. Если пользователь не подтвердил почту, то при попытке залогироватся его перенесет на страницу подтверждения где ему предоставится возможность подтвердить (произойдет обновление кода в базе и отправка нового кода).
3. После успешной авторизации токены будут сохранены в локальном хранилище(file), и при повторном запуске приложение будут подтягиваться токен(access_token) для успешного входа минуя аутентификацию.
4. Если время жизни токена пройдет, вернется соответствующая ошибка, автоматически произойдет вызов метода обновления токена(refresh_token).
5. Если же пройдет время жизни токена(refresh_token), пользователя вернется на главную где ему нужно будет повторно пройти аутентификацию.

## Profile

1. После успешной авторизации, пользовать увидит свой профиль где будет возможность обновить пароль.
2. После изменения пароля, старый сохранится в истории.

## Card

1. При переключение на банковские карты, пользователь увидит сообщение что "список пуст", а после добавления, UI обновится.
2. после выбора определенной карточки можно будет ее удалить или обновить статус на активно/неактивно.
